# API 33 compatibility checkpoint
The real Samsung SM-T875 (Android 13/API 33) connected to the 0.19.1 relay but both app launch and parallel recovery failed. The manifest minimum (30) is not the separate-session minimum. SessionEngineManager.start and VirtualEngine.startInternal both require API 34; VirtualEngine also verifies a trusted owned display group and independent keyguard. The same source requires per-display task ownership and gesture guards. Do not lower the guards to make an eligibility check pass. Do not fall back to primary display.

Use `python3 scripts/check-isolation-compatibility.py --device-api 33 --require-separate` before any new tablet distribution. The current baseline must exit 1. An API-eligible result is not real-device certification. The owner build at a0733689 remains a historical signed baseline, not a working Android 13 isolated engine.

Candidate engines for personal local-only evaluation: Agent-VScreen stable 1.4.1, MIT, Android 11+ advertised (14+ recommended); https://github.com/kilolonion/agent-vscreen/releases/tag/v1.4.1 . Virtual Screen 0.2.1, API 33 advertised, PolyForm Noncommercial, https://github.com/lejw0925/android-virtual-screen/releases/tag/v0.2.1 . Neither is certified on this Samsung. Their protocols differ from Phone MCP; do not point existing ChatGPT plugin at either, expose a public tunnel, add remote shell, or grant additional access merely for a local proof. Evaluate one candidate at a time, initially with network access disabled for the candidate, only neutral test application, no root or lock-screen operation, local visible stop. Verify physical screen unchanged, nonzero display, calculation outcome, local stop, cleanup, and no automatic fallback. Only then evaluate authenticated private integration and its licensing. No actual port or device test has been completed by this audit.
